        Step by step

        Delapan tahap,
        satu alur kripto.

        Setiap kartu memuat nama tahap, rumus, substitusi angka nyata dari sesi, dan hasil. Data rahasia ditandai oranye; data publik ditandai biru.

        The protocol

        Dua lapis kripto.
        Satu paket game.

        Diffie-Hellman menyepakati kunci sesi tanpa mengirimnya. ElGamal mengenkripsi pesan bertopeng dengan kunci publik server.

        Diffie-Hellman

        Pemain memilih a, server memilih b. Masing-masing mengirim A = ga mod p dan B = gb mod p. K = Ba = Ab hanya diketahui kedua pihak.

        • Rahasia tidak pernah melintasi jaringan
        • Keamanan berbasis masalah logaritma diskret

        ElGamal

        Pemain memakai kunci publik server y untuk membuat ciphertext (c1, c2). Hanya server dengan kunci privat x yang dapat membuka pesan bertopeng m′.

        • Enkripsi probabilistik dengan nonce k
        • Ciphertext dua bilangan per pesan

        Saling bergantung

        Sebelum dienkripsi, pesan disamarkan m′ = (m + K) mod p. Server harus memakai x untuk ElGamal lalu K untuk melepas topeng. Tanpa salah satunya, m tidak pulih.

        • Dua rahasia: x milik server, K hasil DH
        • Keterkaitan tahap 2, 3, 4, dan 5

        Teaching simulation: seluruh perhitungan kripto berjalan di Python standard library, tanpa library kriptografi siap pakai.

        Threat view

        Apa yang Eve lihat?

        Penyadap pasif dapat menyalin seluruh trafik. Integritas pesan adalah masalah terpisah dari kerahasiaan.

        Terlihat Eve

        Data publik & ciphertext

        p, q, g, y, A, B, c1, dan c2. Eve juga dapat mengubah c2 sebelum diteruskan ke server.

        • Menyalin paket dan mencoba brute force pada Mode Demo
        • Mengubah ciphertext tanpa diketahui ElGamal polos
        Tidak terlihat

        Rahasia & pesan asli

        a, b, x, k, K, m, dan m′. Untuk mendapatkannya Eve harus memecahkan logaritma diskret atau menebak kunci sesi.

        • DLP pada 128 bit jauh lebih mahal daripada 16 bit
        • Tanpa K, plaintext ElGamal tetap bertopeng
        Keterbatasan

        Malleable & tanpa autentikasi

        ElGamal polos tidak memiliki tag integritas, dan DH polos rentan man-in-the-middle. Perubahan c2 tetap didekripsi menjadi nilai ngawur.

        • Perbaikan: tanda tangan digital, MAC, atau AEAD
        • Perbaikan DH: autentikasi kunci / sertifikat
        MODE DEMO 16 bit — untuk verifikasi manual Mode Aman 128 bit hanya untuk demonstrasi, bukan produksi.
